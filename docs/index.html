Architecture & Philosophy

MicroLLM: Local Hybrid "System One" Decision Engine

Inspired by TypeSafe AI's Jev, MicroLLM is a local probabilistic decision engine engineered for ultra-low latency (< 15 ms on CPU) while satisfying 100% of the 32 MUST requirements of the jevcompat 0.1 specification (POST /v1/systemone).

Protocol Compliance
32 / 32 MUST
Official jevcompat 0.1 contract verified by 58 tests
CPU Latency (Gear 1)
< 2.5 ms
Single-pass non-autoregressive evaluation
Order Bias (Gear 2 L0)
0.000000
Exact mathematical invariance via circular rotation
Why decouple "System One" from "System Two"?
In modern agentic pipelines (routing, safety guardrails, ticket triage, signal extraction), prompting an autoregressive LLM (System Two) to generate free-form text or JSON wastes dozens of tokens, risks schema parsing failures, and suffers from both position bias (preferring option A or the last option) and miscalibrated overconfidence. A System One model evaluates the input state in a single prefill pass and directly returns a calibrated probability distribution over noul (yes/no), choice (2 to 255 options), or score (2 to 10 ordinal levels).

2. Installation & Quickstart

The project is preconfigured in the local virtual environment .venv and requires neither a discrete GPU nor multi-gigabyte model downloads to run out of the box.

.\.venv\Scripts\python -m microllm.server

# 2. Run all automated tests (JevCompat 32/32 MUST, AnyJev L0, RLCD² Trainer, Profiles & Guardrails)

# 3. Pull & quantize an Ollama-style INT8 ONNX profile into ~/.cache/microllm/
.\.venv\Scripts\python -m microllm.server pull fast-cpu-int8
.\.venv\Scripts\python -m microllm.server pull multilingual
.\.venv\Scripts\python -m microllm.server pull guardrail

4. The 3 Decision Primitives: noul, choice, score

Unlike text-completion endpoints, POST /v1/systemone accepts a state (string, JSON object, or JSON array) and a dictionary of named questions. Every question is evaluated in strict isolation (its key name, ordering, or the presence of sibling questions in the batch never alters its probabilities).

4.1 The noul Primitive (Binary Yes / No Proposition)

Returns a single calibrated probability noul $\in (0, 1)$ that the proposition holds true. Per rule noul.answer-shape of jevcompat 0.1, a noul answer must not include an unprefixed confidence field because the binary probability $p \in (0,1)$ already encodes full uncertainty: its distance from $0.5$ ($|2p - 1|$) directly measures certainty.

Request & Response — noul Primitive 
// Request inside "questions":
"urgent_refund": {
  "type": "noul",
  "instructions": "Is the customer requesting an immediate refund?",
  "criteria": {
    "true": "Customer explicitly asks for an immediate refund or money back",
    "false": "General question without refund request"
  }
}

// Response inside "answers":
"urgent_refund": {
  "type": "noul",
  "noul": 0.9142
}

4.2 The choice Primitive (Categorical Selection Across 2..255 Options)

Selects one option among $n \in [2, 255]$ mutually exclusive candidates. The official TypeSafe AI confidence formula is not $\max_i p_i$, but the maximum probability renormalized above uniform chance $1/n$:

Official TypeSafe AI Formula — choice_confidence (src/microllm/confidence.py)
confidence_choice(p) = (n · max_i(p_i) - 1) / (n - 1) ∈ [0, 1]

Thus, a uniform distribution $(1/n, \dots, 1/n)$ yields exactly confidence = 0.0, whereas a degenerate distribution on a single option yields confidence = 1.0.

4.3 The score Primitive (Ordinal Scale Across 2..10 Levels)

Evaluates an ordered intensity rubric across $n \in [2, 10]$ levels indexed $0, 1, \dots, n-1$. The returned score is the mathematical expectation $\mathbb{E}[S] = \sum_{i=0}^{n-1} i \cdot p_i \in [0, n-1]$, and confidence measures concentration around the modal level $k = \arg\max_i p_i$:

Official TypeSafe AI Formula — score_confidence & score_expectation (src/microllm/confidence.py)
E[S] = Σ_{i=0}^{n-1} i · p_i D = (1 / n) · Σ_{i=0}^{n-1} |i - (n - 1) / 2| confidence_score(p) = max(0, 1 - (Σ_{i=0}^{n-1} p_i · |i - k|) / D) where k = argmax_i(p_i)

4.4 The multi Primitive (Independent Multi-Label Classification Across 2..255 Labels)

Evaluates $n \in [2, 255]$ non-mutually-exclusive labels independently (probabilities do not have to sum to $1.0$). Each label $k$ receives an independent calibrated probability $p_k \in (0, 1)$, active labels above threshold (default $0.5$) are returned in labels, and overall multi-label certainty is $\text{confidence}_{\text{multi}}(p) = \frac{1}{n}\sum_{k=1}^n |2 p_k - 1|$.

7. Gear 1: Fast NLI Encoder, Per-$K$ Temperature & Conformal Prediction

Implemented in src/microllm/backends/fast_encoder.py and src/microllm/calibration.py, Gear 1 combines four engineering breakthroughs from openJev-verdict-2.0, VerdictML, and StartLux-Decision:

1. NLI Hypothesis Sentence Templating

Pretrained Natural Language Inference encoders (DeBERTa-v3, ModernBERT, GLiClass) expect complete sentences. The function format_nli_hypothesis(option, description) transforms every candidate into:

"It is {option}: {description}."

This simple alignment boosts zero-shot classification accuracy by +2.1% to +6.9% with zero retraining.

2. Per-Cardinality ($K$) Temperature Scaling

A single global temperature underperforms when option counts $K$ vary from $2$ to $255$. PerKTemperatureScaler fits a dedicated temperature $T_K > 0$ per cardinality via NLL minimization (BFGS) and interpolates linearly in $\log(K)$ for unseen cardinalities.

Split Conformal Prediction with Certified Abstention (SplitConformalCalibrator)
Non-conformity score : s_i = 1 - p_cal(y_i | x_i) Finite-sample (1 - α) q̂ : q̂ = Quantile(s_1..s_N ; ceil((N + 1)(1 - α)) / N) Prediction set : C_α(x) = { k ∈ {1..K} : 1 - p(k | x) ≤ q̂ } Abstention rule : x_abstain = True iff |C_α(x)| > 1
Mathematical Elimination of Position Bias

8. Gear 2: AnyJev $L_0$ Prefill Reader & Van der Corput Schedule

Implemented in src/microllm/backends/prefill_llm.py following Nokia Applied Research's AnyJev Technical Report (arXiv:2610.00831), Gear 2 solves the fundamental flaw of LLMs in decision-making: sensitivity to the order in which candidate options are presented in the prompt.

AnyJev Theorem 1 — Algebraic Cancellation of Slot Bias in Log-Space (l0_circular_rotation_readout)
Additive slot-bias model : log q_t(i) = s_i + b_{(i - t) mod K} - log Z_t Mean across rotations t : z̄_i = (1 / K) · Σ_{t=0}^{K-1} log q_t(i) = s_i + (1 / K) Σ_{j=0}^{K-1} b_j - (1 / K) Σ_{t=0}^{K-1} log Z_t Final L0 distribution : p^{L0} = softmax(z̄) = softmax(s) (completely independent of b_j!)

Van der Corput Schedule & Early Stopping

Instead of visiting circular shifts sequentially ($t = 0, 1, 2, \dots$), van_der_corput_order(K) visits rotations in binary-reflected order $0, \lfloor K/2 \rfloor, \lfloor K/4 \rfloor, \lfloor 3K/4 \rfloor, \dots$ so that every prefix maximally separates option positions. Once $t \ge 2$ and the top-2 log-odds margin exceeds $\tau$ ($\mu(\bar{z}) = \bar{z}_{(1)} - \bar{z}_{(2)} \ge \tau$), evaluation stops early (cutting latency by 2x to 4x).

Canonical Ordering & Empirical Prior Debiasing

For unordered choice questions, AnyJevPrefillBackend canonically sorts option keys before applying the van der Corput schedule, guaranteeing zero order-flip drift (0.0) even when early stopping triggers. For ordinal score questions, the natural level ordering is preserved (AnyJev Appendix E).

9. StartLux "Read-or-Think" Cascade

Implemented in src/microllm/backends/cascade.py (DualGearCascadeBackend), the cascade combines Gear 1's speed with Gear 2's position-unbiased depth using the fusion rule from StartLux-Decision (arXiv:2610.17309):

StartLux-Decision Escalation & Weighted Fusion Rule (α = 0.75)
1. Evaluate p_0 = Gear1(state, question) in < 2 ms. 2. If confidence(p_0) ≥ g AND x_abstain == False: Return p_0 immediately (Fast Auto-Commit). 3. Otherwise (ambiguous case or conformal abstention): Evaluate p_1 = Gear2_AnyJev_L0(state, question) Return p_final = (1 - α) · p_0 + α · p_1 with α = 0.75.
Calibration & Reinforcement Learning

10. Local OpenJev-RLCD & RLCD² Training Pipeline

Implemented in src/microllm/rlcd.py, this module reproduces Algorithm 1 ("Calibrate, then Reinforce") from OpenJev-RLCD (arXiv:2609.38850) enhanced with $\text{RLCD}^2$ difficulty weighting from StartLux-Decision (arXiv:2610.17309).

Proposition 1 (OpenJev-RLCD, p. 3) — Why Group-Mean Scoring Destroys Calibration
J(E_r[u(r)], q) = E_r[ J(u(r), q) ] + E_x[ Var_r(u(r) | x) ] ↳ Scoring the group-averaged prediction E_r[u] adds a variance bonus that rewards arbitrary disagreement across rationales! ↳ OpenJev-RLCD Solution: evaluate the shifted Brier reward J_Brier(u, q) = (1/2) - (1/K) Σ_k (u_k - q_k)² on each rationale individually.

Stage 1: Pathwise Readout Calibration

Minimizes the differentiable Brier loss directly on the decision head logits with $\text{RLCD}^2$ $\text{Beta}(8,2)$ difficulty weighting: $$w(y, q) \propto u^\alpha (1 - u)^\beta, \quad u = 1 - q_y$$ This stage removes initial overconfidence and brings readout probabilities into the region where RL gradients are informative.

Stage 2: Leave-One-Out REINFORCE + KL Anchor

Samples a group of $G=4$ latent rationales per question, computes the KL-regularized reward against the frozen Stage 1 policy ($\beta = 0.04$, clip $c = 0.3$): $$\tilde{R}_i = R_{\text{Brier}}(u^{(i)}, y) - \beta \cdot \min\big(c,\; D_{\text{KL}}(u^{(i)} \,\|\, u^{\text{ref}})\big)$$ and applies the Leave-One-Out baseline $A_i = \tilde{R}_i - \frac{1}{G-1}\sum_{j \ne i}\tilde{R}_j$.

Python Integration & Open-Source Models

11. Typed Python SDK (MicroJevClient) & HuggingFace / ONNX Adapters

The client SDK (src/microllm/client.py) provides a strongly-typed API that validates inputs locally and returns structured NoulResult, ChoiceResult, and ScoreResult objects:

Python — Using the Typed MicroJevClient SDK 
from microllm import MicroJevClient, Noul, Choice, Score

client = MicroJevClient(base_url="http://127.0.0.1:8000")

res = client.ask(
    state="I was billed twice for invoice #4092! Please refund the duplicate charge today.",
    questions={
        "is_refund": Noul(
            instructions="Is the customer requesting an immediate refund?",
            true_description="Customer asks for a refund or money back",
            false_description="No refund mentioned",
        ),
        "department": Choice(
            options={
                "billing": "Invoices, double charges, refunds",
                "technical": "Bugs, crashes, API outages",
                "shipping": "Delayed package, lost parcel",
            },
            instructions="Which department should handle this?",
        ),
        "urgency": Score(
            levels=["Low", "Medium", "High / Immediate"],
            instructions="How urgent is this request?",
        ),
    },
)

print(res["is_refund"].value, res["is_refund"].probability)      # True, 0.914
print(res["department"].value, res["department"].confidence)    # "billing", 0.782
print(res["urgency"].value, res["urgency"].score)               # "High / Immediate", 1.74

Plugging in an Open-Source HuggingFace or ONNX Runtime Model (Approach 1 + 2)

To avoid reinventing the wheel, FastEncoderBackend and AnyJevPrefillBackend accept any external scorer via the logit_scorer parameter or the built-in factories in microllm.backends.base:

Python — Injecting a HuggingFace NLI or ONNX Runtime Encoder 
from microllm.backends.base import create_hf_zero_shot_scorer, create_onnx_nli_scorer
from microllm.backends.fast_encoder import FastEncoderBackend
from microllm.backends.prefill_llm import AnyJevPrefillBackend

# Option A: HuggingFace NLI Model (requires: pip install microllm[torch])
hf_scorer = create_hf_zero_shot_scorer("MoritzLaurer/DeBERTa-v3-small-mnli-fever-anli")
gear1_hf = FastEncoderBackend(logit_scorer=hf_scorer)
gear2_hf = AnyJevPrefillBackend(logit_scorer=hf_scorer)

# Option B: INT8 Quantized ONNX Runtime Session on CPU (requires: pip install microllm[onnx])
onnx_scorer = create_onnx_nli_scorer("models/deberta-v3-small-int8.onnx")
gear1_onnx = FastEncoderBackend(logit_scorer=onnx_scorer)
